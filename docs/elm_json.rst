===============================
ELM JSON serialization notes
===============================

This page documents important details about the shape of the ELM JSON generated by ELM Flow, to help consumers integrate reliably.

Top-level schemaIdentifier
=========================

For compatibility with common ELM consumers and our test suite, ELM Flow surfaces the schema identifier at the document root in addition to the library section.

Specifically, ELMDocument.to_dict() returns a mapping with both:

- library: The full ELMLibrary payload, which itself contains library.schemaIdentifier
- schemaIdentifier: A duplicated schema identifier at the document root

This ensures tools that expect the schema at the top-level can validate the ELM payload without traversing into the library object.

Example (abridged):

.. code-block:: json

  {
    "library": {
      "identifier": { "id": "TestLib", "version": "1.0.0" },
      "schemaIdentifier": { "id": "urn:hl7-org:elm:r1", "version": "r1" },
      "statements": { "def": [] }
    },
    "schemaIdentifier": { "id": "urn:hl7-org:elm:r1", "version": "r1" }
  }

Type inference of numeric string literals
=========================================

When expression definitions provide raw string expressions (for example, from parsed text) in ExpressionDef.expression without expression_text, ELM Flow infers Integer for simple numeric literals represented as strings (e.g., "42"). This improves consistency for mixed sources where some expressions arrive pre-parsed and others as text.

API responses normalization
===========================

The FastAPI layer normalizes results from different converter backends to consistently expose:

- success: bool
- elm_json: object (document dict) when available
- errors, warnings: lists of strings

This helps clients consume responses uniformly, regardless of the specific converter path taken.

Versioning and compatibility
============================

- schemaIdentifier duplicates at the top-level and inside library are maintained for compatibility with tests and downstream tools.
- If you have consumers that only expect the library-level field, you can ignore the top-level one safely.
